# Instruções do Projeto Folium

## Antes de Começar
1. `npm install`
2. Copie `.env.example` para `.env.local` e preencha as variáveis Supabase + Google OAuth
3. Configure o projeto Supabase (ver docs/02-stack.md)
4. `npm run db:push` (cria as tabelas no banco Supabase)
5. `npm run db:generate` (gera os tipos Prisma)
6. `npm run dev` → http://localhost:3000

## Padrão de Commits
- `feat: descrição` - nova funcionalidade
- `fix: descrição` - correção de bug
- `docs: descrição` - documentação
- `style: descrição` - formatação/CSS
- `refactor: descrição` - refatoração sem mudança de comportamento
- `chore: descrição` - tarefas auxiliares

## ⚠️ IMPORTANTE - ATUALIZAÇÃO DE PORTFÓLIO
Após CADA commit com `feat:` ou `fix:`:
1. Edite `.project.md` → seção "Última Atualização"
2. Atualize o % de "Progresso" se avançou o escopo
3. Rode `python AgenteMestre/sincronizar_portfolio.py`

## Estrutura do Projeto
```
folium/
├── src/
│   ├── app/           ← rotas Next.js (App Router)
│   ├── components/    ← UI reutilizável
│   ├── lib/           ← supabase client, utils, validações
│   └── types/         ← tipos TypeScript
├── prisma/
│   └── schema.prisma
├── supabase/
│   └── migrations/
├── public/
│   └── default-card.svg
├── docs/              ← documentação do projeto
├── .env.example
├── .project.md        ← ATUALIZAR EM CADA MUDANÇA
└── .instructions.md   ← ESTE ARQUIVO
```

## Regras de Desenvolvimento
- Sempre criar branch antes de features grandes (`feat/nome`)
- RLS ativo em todas as tabelas Supabase — nunca desativar
- Markdown para conteúdo de ensaios — nunca HTML cru
- Rate limiting em todas as rotas de escrita
- Testar fluxo Google OAuth localmente antes de commit
